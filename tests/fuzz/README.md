# `.apta` parser fuzzing

This directory contains the bounded fuzzing entry point for untrusted `.apta` container input.

## Targets

- `apta_wovr_reader_fuzz` passes every generated byte sequence to `apta_result_parse()` using strict parsing and bounded resource limits.
- `apta_wovr_seed_generator` creates five canonical corpus entries:
  - `valid-final.apta`;
  - `valid-sparse-partial.apta`;
  - `valid-wdtl.apta`;
  - `valid-meta.apta`;
  - `valid-s4.apta`.
- `apta_s6_seed_generator` creates `valid-s6.apta`.
- `wovr_reader.dict` supplies container magic, all currently recognized
  FourCC values, version fields, lifecycle/revision values, tempo constants
  and common waveform/CBOR tokens to libFuzzer.

## Local sanitized build

```sh
CC=clang CXX=clang++ cmake -S . -B build-fuzz \
  -DAPTA_BUILD_TESTS=ON \
  -DAPTA_ENABLE_SANITIZERS=ON \
  -DAPTA_BUILD_FUZZING=ON \
  -DCMAKE_BUILD_TYPE=Debug

cmake --build build-fuzz --parallel
ctest --test-dir build-fuzz --output-on-failure
```

## Generate the seed corpus

```sh
mkdir -p build-fuzz/corpus
cd build-fuzz/corpus
../tests/apta_wovr_seed_generator
../tests/apta_s6_seed_generator
cd ../..
```

The seed generators use the current public analysis and serialization API
instead of embedding stale binary fixtures. A format or writer change therefore
regenerates corpus entries through the same canonical path used by
applications.

## CI-equivalent smoke run

```sh
./build-fuzz/tests/apta_wovr_reader_fuzz \
  build-fuzz/corpus \
  -dict=tests/fuzz/wovr_reader.dict \
  -runs=2000 \
  -max_len=4096 \
  -timeout=5
```

This smoke run detects immediate crashes, sanitizer findings, leaks and regressions in known parser paths. It is intentionally bounded so normal CI remains predictable.

## Longer local run

```sh
./build-fuzz/tests/apta_wovr_reader_fuzz \
  build-fuzz/corpus \
  -dict=tests/fuzz/wovr_reader.dict \
  -max_len=1048576 \
  -timeout=10 \
  -max_total_time=3600
```

Crashing or timeout-inducing inputs MUST be minimized and committed as dedicated regression tests or retained in a reviewed regression corpus. Randomly generated corpus growth SHOULD NOT be committed without demonstrating additional structural coverage.

## Harness limits

The current harness caps:

- input size at 1 MiB through parse options;
- aggregate parsed-result allocation at 1 MiB;
- context-owned memory at 2 MiB;
- section count at 64;
- overview spans at 4096;
- waveform columns at 65536.

These limits are fuzzing policy, not universal library maxima.
